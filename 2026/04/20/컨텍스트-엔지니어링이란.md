## 컨텍스트 엔지니어링이란

Claude Design이 새로 공개되었다는 말을 듣고, 이를 이용해보기 위해 프로젝트를 구성하던 도중 컨텍스트 엔지니어링이라는 개념을 알게 되었다.

프롬프트 엔지니어링과 컨텍스트 엔지니어링에 대한 이야기는 종종 들어보았지만 이를 직접 활용해본 적은 없었는데, 이번 기회에 직접 도입하여 AI로 좋은 디자인을 만들어 보기로 했다.

### 컨텍스트 엔지니어링이란?

> 컨텍스트 엔지니어링은 AI 모델이 판단을 내리기 전에 참고하는 정보 페이로드(Information Payloads)를 체계적으로 설계하고 최적화하는 과정이다.

#### 컨텍스트 엔지니어링의 특징

- 동적 정보 조립: 컨텍스트를 단순 프롬프트가 아닌 (Instruction), 지식(Knowledge), 도구(Tools), 메모리(Memory), 상태(State)를 조합한 결과로 정의한다.

- 주의 집중 예산(Attention Budget) 관리: LLM은 컨텍스트가 길어질수록 정확도가 떨어지는 컨텍스트 부패(Context Rot) 현상을 겪는다. 노이즈를 제거하고 중요한 정보만 남겨서 에이전트의 주의력을 최적화한다.

- 적시(Just-in-time) 컨텍스트 주입: 모든 데이터를 바로 제공하지 않고 필요한 시점에만 도구를 사용하여 관련 컨텍스트를 로드하느 점진적 공개(Progressive Disclosure) 전략을 사용한다.

### 프롬프트 엔지니어링 vs 컨텍스트 엔지니어링

> 무엇을 어떻게 물어볼 것인지에 대한 **단순 지침** vs 지침이 해석되는 **정보 환경** 전체 설계

| 구분 | 프롬프트 엔지니어링 | 컨텍스트 엔지니어링 | 
| --- | --- | --- |
| 컨텍스트 모델 | 정적인 단일 문자열 | 동적이고 구조화된 여러 구성 요소의 조합 |
| 주요 목표 | 최적의 문구를 통한 응답 품질 향상 | 정보 처리 시스템 최적화를 통한 성능 극대화 |
| 정보 원천 | 프롬프트 내의 고정된 정보 | 외부 DB, 메모리, 도구 등 다양한 소스에서 동적 융합 |

**주요 차이점**

- 지침 vs 정보 제공: 
    - 프롬프트 엔지니어링은 답변해야 하는지 가르치는 지침(Instruction)
    - 컨텍스트 엔지니어링은 상황에 맞는 최적의 정보(지침, 상태, 메모리, 도구 등)만 선별하여 제공

- 진화된 형태: 컨텍스트 엔지니어링은 프롬프트 엔지니어링의 자연스러운 발전 단계
    - 기존: 최적화된 프롬프트 작성
    - 현재: 시스템 프롬프트, 도구 명세, 메시지 기록 등 전체 컨텍스트 상태를 관리하는 전략 중시

- 장기 기억 유지: 컨텍스트 엔지니어링은 대화가 길어질 때 이를 요약하는 **압축(Compaction)** 기술이나, 중요한 결정을 별도 파일(예: `NOTES.md`)에 기록하여 나중에 다시 가져오는 구조화된 노트 작성 등의 기법을 통해 모델의 기억 한계를 극복한다.

### 컨텍스트 엔지니어링의 구성 요소

- 시스템 프롬프트:
AI 판단 기준을 설정하기 위한 모델의 역할, 규칙, 제한 조건 정의

- 대화 이력 & 상태:
맥락에 맞는 일관된 추론이 가능하도록 대화 흐름과 현재 작업 단계 유지 및 관리

- 장기 기억:
사용자 선호, 과거 대화, 이전 행동 정보를 축적해 개인화된 판단 환경을 점진적으로 형성하는 메커니즘

- RAG(검색 기반 외부 정보 증강):
외부 문서, 데이터베이스, API 등에서 필요한 정보를 검색해 컨텍스트로 주입함으로써 모델의 지식 한계 보완

- 도구 호출:
외부 시스템이나 기능을 실행할 수 있도록 연계해, AI가 실제 업무를 수행할 수 있는 주체로 확장되도록 하는 요소

- 출력 포맷 정의:
AI의 출력 형식을 구조화해 결과를 후속 시스템 처리나 자동화 흐름과 쉽게 연동할 수 있도록 하는 장치

### 7단계 계층적 프롬프트 설계

1. Domain Research     → 업종별 UX 패턴, 경쟁사 인사이트
2. User Journey        → 핵심 사용자 흐름, 전환 포인트  
3. Emotional Design    → 감성 키워드, 무드 컨셉
4. Identity & Goal     → 브랜드 정체성, 목표
5. Design System       → 컬러, 타이포, 컴포넌트
6. Component Specs     → 핵심 컴포넌트 상세 정의
7. Micro-interactions  → 애니메이션, 인터랙션 패턴

#### 1. Domain Research

> 디자인을 시작하기 전, 사용자가 기대하는 검증된 UX 패턴을 AI에게 먼저 정의해 주는 단계

**분석해야 할 요소**

- 업계 Top 3 서비스 분석
- 사용자가 기대하는 패턴
- 신뢰 시그널(인증 배지, 리뷰)
- 경쟁사의 Pain Point

프롬프트 반영 예시: "펫 서비스 도메인의 Top 3 경쟁사를 분석하고, 사용자가 이 업종에서 기대하는 핵심 패턴인 '프로필 카드'와 '예약 캘린더'에 대한 UX 전략을 수립해줘"

```markdown
## Domain Context
This is a pet sitter matching service. Key UX expectations:
- Profile cards with verification badges (like Rover)
- Availability calendar integration
- Trust signals: ID verification, insurance, reviews
- Real-time service reports with photos (like Wag)

Competitor insights:
- Rover: Strong on verification, weak on personality
- Wag: Great real-time tracking, complex booking flow
→ Opportunity: Combine trust + simplicity + warmth
```

#### 2. User Journey 

> 사용자의 심리적 여정에 따라 페이지 구성, 사용자 흐름 파악

**설계 포인트**

`[진입] → [발견] → [평가] → [결정] → [행동] → [유지]`

1. 진입(Entry): 서비스 핵심 가치 이해
2. 발견(Discovery): 사용자에게 필요한 것 찾기
3. 평가(Evaluation): 이게 괜찮은지
4. 결정(Decision): 최종 확인
5. 행동(Action): 빠른 완료
6. 유지(Retention): 재사용

프롬프트 반영 예시: "진입 단계에서는 사용자가 3초 안에 핵심 가치를 이해할 수 있도록 명확한 헤드라인과 비주얼을 배치하고, 평가 단계에서는 실제 리뷰를 강조해줘"

```markdown
## User Journey Considerations
Structure the page to match the user's psychological journey:

1. Hero: Address "what is this?" → Clear value prop + trust stats
2. How it Works: Reduce "seems complicated" → 3 simple steps  
3. Featured Items: Enable discovery → Curated, not overwhelming
4. Trust Section: Answer "can I trust this?" → Badges + reviews
5. CTA: Remove final friction → Clear pricing, guarantees
```

#### 3. Emotional Design  

> 서비스가 사용자에게 불러일으켜야 할 핵심 감정과 무드를 시각적 요소로 정의

포함 요소: 감성 키워드(신뢰, 따뜻함, 에너지 등), 키워드별 컬러 방향성, 타이포그래피 분위기, 이미지 스타일

프롬프트 반영 예시: "펫시터 매칭 서비스로서 '신뢰(70%)'와 '따뜻함(30%)'의 밸런스를 맞춰줘. 블루 컬러와 부드러운 모서리, 친근한 일러스트를 사용해줘"

```markdown
## Emotional Direction
Primary emotions and their visual translation:

- Trust (50%): Clean layouts, verification badges prominently displayed,
  real photos, consistent spacing, emerald green for verified states
- Warmth (35%): Rounded corners (12-16px), amber/orange accents,
  soft shadows, friendly illustrations, cream backgrounds  
- Ease (15%): Generous whitespace, clear CTAs, minimal form fields

Overall feel: "Like leaving your pet with a trusted friend who happens
to be a professional" - NOT cold/corporate, NOT chaotic/playful
```

#### 4. Identity & Goal 

> 구체적인 브랜드 정보와 디자인의 최종 목표를 명확히 하여 방향성 정의

포함 요소: 브랜드 이름, 핵심 미션, 타겟 유저, 이번 디자인을 통해 달성하고자 하는 비즈니스 목표

프롬프트 반영 예시: "브랜드 이름은 'PetPal'이야. 프리미엄 펫 케어를 지향하며, 사용자가 신뢰를 바탕으로 빠르게 예약을 확정하게 만드는 것이 목표야"

**정의해야 할 요소**
```markdown
Service Name: [이름]
One-liner: [10단어 이내 설명]
Category: [도메인 카테고리]
Positioning: [경쟁사 대비 차별점]
Primary Goal: [메인 전환 액션]
Secondary Goal: [서브 액션]
Brand Personality: [3가지 형용사]
```

```markdown
Service Name: PetPal (펫팔)
One-liner: 검증된 이웃 펫시터와 우리 아이를 연결합니다
Category: Pet Care / O2O Marketplace
Positioning: "보험 + 신원인증 + 실시간 리포트"로 가장 안심되는 펫시터 매칭
Primary Goal: 펫시터 예약 완료
Secondary Goal: 펫시터 회원가입 유도
Brand Personality: 따뜻한, 믿음직한, 전문적인
```

#### 5. Design System 

> AI가 실제로 구현할 때 사용할 구체적인 기술 스펙을 정의하는 단계

**포함 요소**

- 용도별 컬러 팔레트(Primary, Secondary 등)
- 타이포그래피(폰트 종류, 크기)
- 간격 및 그리드 시스템(8px 그리드 등)

프롬프트 반영 예시: "Primary 컬러는 Indigo(#4F46E5)를 사용하고, 모든 텍스트는 Inter 폰트를 적용해. 간격 규칙은 8px 단위를 기본으로 해줘"

**Color System**

단순히 "파란색"이 아니라, 용도별로 완전한 팔레트 정의

```
Primary:     #F59E0B (Amber)      - CTAs, 핵심 액션
Secondary:   #10B981 (Emerald)    - 인증 배지, 신뢰
Accent:      #8B5CF6 (Violet)     - 프리미엄, 특별 기능
Background:  #FFFBEB (Cream)      - 따뜻한 베이스
Surface:     #FFFFFF (White)      - 카드, 모달
Text Primary:#292524 (Stone 800)  - 제목, 본문
Text Muted:  #78716C (Stone 500)  - 보조 텍스트
Success:     #10B981              - 완료, 인증됨
Warning:     #F59E0B              - 주의
Error:       #EF4444              - 오류
```

**Typography**

```
Headings: Nunito (700, 800) - 둥근 느낌, 친근함
Body: Inter (400, 500) - 가독성, 현대적

Scale (1.25 ratio):
- H1: 36px
- H2: 28px  
- H3: 22px
- Body: 16px
- Caption: 14px
```

**Spacing & Components**
```
Base unit: 8px
Border radius: 12px (버튼), 16px (카드)
Shadows: Soft (rgba 낮은 opacity)
```

#### 6. Component Specs 

> 해당 도메인에서 핵심이 되는 컴포넌트의 상세 구성 정의

포함 요소: 도메인 특화 컴포넌트(예: 펫시터 카드, 프라이싱 테이블, 진도바)의 내부 데이터 구성 및 레이아웃

프롬프트 반영 예시: "펫시터 카드 컴포넌트에는 사진, 별점, 시간당 가격, 활동 지역, 검증 배지를 포함하고 모바일에서도 가독성이 좋게 설계해줘"

예시 - Sitter Card (펫시터 카드)
```markdown
[Sitter Card]
├── Purpose: 시터 목록에서 핵심 정보 전달 + 클릭 유도
├── Contents:
│   ├── 프로필 사진 (80x80, 원형)
│   ├── 이름 + 인증 배지
│   ├── 별점 + 리뷰 수
│   ├── 거리
│   ├── 서비스 태그
│   └── 가격
├── States:
│   ├── Default: 흰 배경, 약한 그림자
│   ├── Hover: 4px 상승 + 그림자 강화
│   └── Favorite: 하트 filled
└── Responsive:
    ├── Desktop: 3열
    ├── Tablet: 2열
    └── Mobile: 1열
```

#### 7. Micro-interactions

> 정적인 디자인을 넘어 움직임을 통해 브랜드 경험을 강화

포함 요소: 인터랙션 유형(등장, 피드백, 상태 전환, 네비게이션), 타이밍 스펙(ms 단위), 가속도(Easing) 값

프롬프트 반영 예시: "버튼 클릭 시 200ms(ease-out) 속도로 피드백 애니메이션을 적용하고, 새로운 콘텐츠 등장 시에는 아래에서 위로 슬라이드 되게 해줘"

**스펙 정의 방법**
```
Trigger: 시터 카드 호버
Animation: translateY(-4px) + shadow 강화
Duration: 200ms
Easing: ease-out
Purpose: 클릭 가능함을 암시, 살아있는 느낌

Trigger: 즐겨찾기 클릭
Animation: 하트 scale 1.3 → 1 + fill
Duration: 300ms  
Easing: spring
Purpose: 기분 좋은 피드백, 액션 확인
```

### 전체 프롬프트 예시

```markdown
Build a warm, trustworthy landing page for 'PetPal', a pet sitter matching 
platform that connects pet owners with verified, caring neighborhood sitters.

## Domain Context
Reference: Rover (verification), Wag (real-time tracking)
Key patterns: Profile cards, availability calendar, trust badges
Opportunity: Combine trust + simplicity + warmth

## User Journey
1. Hero → Answer "what is this?" with clear value prop
2. How it Works → Reduce complexity with 3 steps
3. Featured Sitters → Enable discovery without overwhelming
4. Trust Section → Answer "can I trust this?"
5. CTA → Remove friction with clear pricing

## Emotional Direction
- Trust (50%): Badges, real photos, emerald accents
- Warmth (35%): Rounded corners, amber/cream, illustrations
- Ease (15%): Whitespace, minimal forms

## Design System
Colors: Primary #F59E0B, Secondary #10B981, Background #FFFBEB
Typography: Nunito headings, Inter body
Spacing: 8px base, 12-16px radius, soft shadows

## Key Components
- Sitter Card: Photo, badges, rating, distance, price, hover lift
- Trust Badges: Verified, Insured, Response rate
- Booking Flow: 3 steps max

## Interactions  
- Cards: Hover lift 4px, 200ms ease-out
- Favorite: Heart scale bounce, 300ms spring
- Page load: Sections fade in on scroll

## Requirements
- Mobile-first responsive
- Korean language primary
- Accessibility: Focus states, contrast
```

### 단계별 개선 프롬프트 예시

```
Phase 1: "먼저 전체 섹션 구조와 컬러 시스템만 잡아줘."

Phase 2: "히어로 섹션을 개선해줘. 검색바를 더 눈에 띄게."

Phase 3: "시터 카드 디자인을 정교하게. 호버 시 정보 확장되도록."

Phase 4: "신뢰 섹션 강화. 숫자 카운트업 애니메이션 추가."

Phase 5: "전체 인터랙션 추가. 스크롤 fade-in, 버튼 호버."

Phase 6: "모바일 버전 점검. 하단 네비게이션 추가."
```
