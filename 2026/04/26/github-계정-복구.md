## 깃허브 계정 복구 성공

> 2026-04-26

이전 이야기: [깃허브 계정이 suspend 상태로 전환됨](https://github.com/kusuri12-10/retrospective/blob/main/2026/04/15/github%20account%EA%B0%80%20suspended%20%EC%83%81%ED%83%9C%EB%A1%9C%20%EC%A0%84%ED%99%98%EB%90%A8.md)

깃허브 계정이 정지된 이후 상당히 힘든 시간을 보냈다.

프로젝트 회의할 때 개발 관련 이야기나 깃허브 이야기가 나오면 현재 깃허브 계정이 서스펜드 상태라 문의를 기다리는 중이라는 답변을 자주 해야만 했다.

또 개발을 하지 않을 수는 없었기에 새로운 계정을 생성하여 커밋을 해야했고, 기존 organization에 새로운 계정을 추가해야 하는 번거로운 점도 있었다.

가장 큰 문제점은 기존 개인 레포지토리에 액세스할 수 없었다는 점이다. 크게 중요한 레포지토리가 있진 않았으나, 그동안의 기록이 사라진다는 상실감이 컸다. 또한 기존 깃허브 계정으로 OAuth 로그인이 되어있는 서비스를 이용할 수 없는 문제 등 다양한 문제를 겪어볼 수 있었다.

### 계정 복구

그러나 당일 새벽 3시, 중간고사 공부를 하던 중 메일이 한 통 날아왔다.

드디어 기다리던 github support team의 메일이 온 것이다!

번거롭게 추가로 제공해야 할 사항은 없엇고, 계정의 상태가 전환되었으니 다시 로그인해도 된다는 내용이었다.

졸면서 공부하던 중에 정신이 번쩍 뜨였다. 허겁지겁 깃허브 계정으로 로그인하니 드디어 그리운 원래 계정으로 돌아올 수 있었다.

너무 기쁜 나머지 깃허브 측의 실수였음에도 부족한 영어 실력으로 메일을 써서 답장을 보냈다. 

다른 서비스들은 기존에 사용하던 깃허브와 달리 제공되지 않는 서비스도 있어서 이전하기 어려울 것 같다는 생각이 들었기에, 계정이 복구된건 상당히 다행이었다. 

다른 온라인 저장소들은 github actions, copilot, github와 연동되는 다른 서비스들(vercel 등)을 이용하기 어렵거나 불편하다는 단점들이 있었기에 깃허브를 떠날 수 없었다

다음에는 이런 상황이 발생하지 않도록 기도하는(...) 것 외에는 답이 없을 것 같다. 혹시 이럴 경우를 대비해서 데이터를 백업하는 등의 과정이 필요할 것 같다.
