## 2026 대크톡 서울 참여록

### 들어가기 전

대크톡(Daeke Talk)은 대덕소프트웨어마이스터고등학교(통칭 대마고)의 재학생과 졸업생이 경험을 공유하는 대마고만의 특별한 행사이다. 이 글에는 2026 대크톡 행사에 참여한 뒤 개인적으로 느낀 점을 정리한 내용이 작성하였다.

#### 1. 7기 안진우 선배님

BlockChian 분야

- Blockchain DevOps란?

수직적 확장이 아닌 수평적 확장, k8s를 별로 사용하지 않음

슬래싱(slashing) 처리 -> 서버가 멈춰도 네트워크가 죽지 않도록

기존 인프라 데브옵가 처리하던 일:

- validator 배포, uptime 모니터링
- k8s, terraform, argoCD

블록체인 관련 업무는 위와 좀 다름

일하면서 실제로 중요했던 것
- 깊이가 넓이를 만든다: 한 분야, 도메인을 깊게 공부하는게 빠르게 복리가 붙음
- 프로덕션이 사람을 만든다: 직접 해보는게 중요
- 공개적으로 쓰라: 링크드인 등 활용

대마고 학생들에게
- 남들보다 빠른 시작으로 프로덕션 경력이 빠르게 쌓임, 나이 이용
- 한 분야를 골라서 깊이 파는게 좋음
- 깃헙, 블로그, 발표 등 보이는 곳에서 하기

---

기술 관련 부분은 인프라 부분에 대한 이해도가 낮기도 하고, 블록체인에 대한 지식이 거의 없어서 작성하는 데 어려움이 있었다. 위 부분은 나중에 인프라에 대해서 더 공부할 일이 있을 때 알아보고자 한다.

해당 발표를 듣고 그동안 전혀 작성하지 않았던 블로그 등을 작성해보는게 어떨지 생각해보게 되었다. 사실 회고를 작성하게 된 계기도 눈에 보이는 결과물을 만들어보고자 시작하게 된 것이였어서 위 부분을 다시 생각해보게 되었다.

#### 2. 3기 백광민 선배님

개발자가 서비스 기획에 참여하는 법
- 현업에서 적극적인 개발자들은 서비스 기획 시 의견을 냄, 기획자만 기획 X

기획 방식 비교

- 학교 | 아이디어 -> 기능 정의 -> 개발
- 회사 | 문제 발견 -> 고객 정의 -> 시장 분석 -> 기능 정의 -> 개발
```
문제점 발견: 리서치 회사에서 설문 결과를 수집 시 큰 비용 지출 발생

시장 분석: 명확한 근거 발견

차별화 전략: 토스 데이터 기반으로 데이터 집계
```
사례: 토스플레이스 신분증 검사 서비스

> 미성년자 위조 신분증 문제

**1. 기존 문제점**

기존 신분증 검사 앱이 요구하는 절차가 너무 많음 -> 직원 교육 비용 발생, 번거로움

=> 토스 단말기로 체크하는 서비스 개발

**2. 서비스 구조**

모바일 신분증 인식 -> 영지식 인증 -> 카드 단말기에 표시

**3. 법적 처리**

- 기술적으로 가능하다고 해서 기획이 끝나는게 아님, 여러가지 처리가 필요함(법률, 시장 분석 근거 등)
- 개인정보 수집에 대한 법률 등 법률 처리
- 정책 시연까지 발생
```
문제 발견 -> 시장 분석 -> 기술 가능성 검토 -> 규제 및 법률 검토 -> 서비스 구조 설계
```

학교해서 했던 프로젝트
- 블록체인 티켓
- 도메인 가격 비교
- 웹 기반 이두이노 ide

-> 결국 비슷비슷한 기술 사용, 아이디어에 속지 말자

단순 crud에서 얻기 어려운것들
- 대량 데이터 처리
- 외부 서비스 연동
- 배치 처리
- 시스템 구조 설계

추천 프로젝트

**1. 우편번호 검색 서비스**
- 배울 수 있는 것
    - 수백만 건 주소 데이터 처리
    - 검색 알고리즘 / 자동완성
    - API 처리
    - 배치 처리
- 계속 변화하는 주소를 계속 어떻게 처리할 지 고민
- 수백만 건 마이그레이션하면서 서비스 장애를 막는 고민을 해보는 신입은 얼마 안됨

**2. 음악 재생목록 이전 서비스**
- 스포티파이, 유튜브 뮤직, FLO, 멜론 등 재생목록 이전
- 배울 수 있는 것
    - 여러 외부 API 연동, 스크래핑
- 같은 곡인데 제목이 다를 경우 등 예외 사항

프로젝트 고를 때 확인해야할 것
- 공공데이터 / 외부 api
- 대량 데이터 처리

중요한 것
- 기초 지식: 프레임워크는 변화하지만 네트워크는 변화하지 않음
- 완벽한 포폴보다 삽질 기록(실패 기록) -> 적당히 실패 기록 쓰기

---

항상 어떤 프로젝트를 해야할 지 고민을 자주 했었는데, 대량 데이터 처리 경험을 해보는 것도 좋겠다고 생각했다. 또 딥다이브 이야기가 계속 강조되는 걸 느꼈다. 최근에 백엔드와 프론트를 번갈아가면서, 또 프레임워크도 하고 싶은걸 그때그때 골라가면서 다양한 시도를 해보고 있었는데, 이 방식도 나쁘진 않지만 이렇게만 했다가는 기초 지식이 늘지 않을거라는 생각이 들었다. 다시 초심으로 돌아가서 서버 기초 지식과 네트워크 지식 등 웹 개발에 기초가 되는 내용을 공부해보아야겠다고 생각했다.
